# algo-tracker · 刷题沉淀系统使用手册

这套文件的目标：**让复习由数据驱动**——每天打开错题本就知道该重做哪几题，每周看一次卡点分布就知道弱点在哪个专题。记录为"重做"服务，不为"重读"服务。

## 文件分工

| 文件 | 层 | 记什么 |
|---|---|---|
| `错题本.md` | 题目层 | 只记卡壳的题和看题解才做出的题 |
| `专题笔记/` | 知识层 | 一个专题一页，只写解题模型，不写题 |
| `进度表.md` | 进度层 | 专题周数跟踪 + 每日打卡计数 |

## 每天的固定流程（管理开销约 5 分钟）

### 1. 开刷前（1 分钟）
打开 `错题本.md`，扫表格里「下次复习」日期 ≤ 今天的行——这就是今天的复习题。先重做它们：**盲写**，不看破题点；写不出来再看，看完合上继续写。

### 2. 刷题中（25 分钟法则）
1. 一道新题给自己 25 分钟独立思考；
2. 25 分钟没思路 → 直接看题解（零基础阶段这是学习，不是作弊）；
3. 看懂后**关掉题解重写**，直到 AC，不照抄；
4. 写完跑测试用例，问自己一句：「这题的关键性质是什么？」

### 3. 收尾（5 分钟）
- 卡壳题 / 看题解才做出的题 → 在错题本**加一行**（一次通过且 20 分钟内搞定的题不进错题本）；
- 复习过的题 → 更新「下次复习 / 连续通过 / 状态」；
- 在进度表打卡一行。

### 4. 每周日（机动日，10 分钟周复盘，不安排新题）
- 错题本按「卡点」列数一数：哪类卡点最多？集中在哪个专题？
  - ① 没思路集中 → 说明该专题的解题模型没建立，重看专题笔记；
  - ② 有思路写不出 → 熟练度问题，多是链表/树类指针操作，多重做；
  - ③ 边界/复杂度错 → 适用条件理解不深，把坑补进专题笔记的易错点。
- 进度校准：本周计划 vs 实际，偏差超过 3 天就顺延并调整后续专题周数。

## 三条铁律

1. **不抄题解、不抄代码。** 完整代码永远在 LeetCode 提交记录里，誊抄是负资产。
2. **破题点必须用自己的话写，不超过 2 句。** 用自己的话写不出来的地方，就是还没真懂的地方——回到题解重看，而不是抄。
3. **复习 = 盲写重做。** 通过判定：不看任何提示，20 分钟内 AC，且能口述时间/空间复杂度。

## 复习间隔规则

学完当天 → 次日（D+1）→ 第 3 天（D+3）→ 第 7 天（D+7）→ 第 21 天（D+21，毕业）。

- 复习通过 → 按序列推进到下一档，日期填实际日期；
- 复习卡壳 → 重置为明天，连续通过清零，并按新表现更新「卡点」列；
- D+21 通过 → 状态改「毕业」，之后只在 Hot100 冲刺阶段自然重现。

## 升级路径

当前是纯 Markdown 手动维护，这是刻意的：先用最轻的方式把习惯跑起来，比一开始上重工具更重要。如果之后觉得「扫到期题」麻烦，两个升级方向：

1. 加一个 20 行左右的 Node 脚本，自动解析错题本表格、输出今天到期题（表格格式固定，解析很简单）；
2. 迁到 Notion 数据库：「到期日 ≤ 今天」做视图筛选，「卡点」做分组统计。
