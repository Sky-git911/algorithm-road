# 通过≠确信：自评「碰运气」是真信号（59 边界版）

59 D+3 通过，但用户自评「对边界的判断还是有些模糊，有点碰运气」。核查属实：其写法把课上的两道独立 guard（`top <= bottom`、`left <= right`）换成合并的严格 guard（`top < bottom && left < right`）。该写法在方阵上全部正确（n=1..40 实测），但依赖一个方阵独有的隐含前提——上段、右段走完后，剩余区域只可能是单格或空，于是被 guard 挡掉的下段/左段可以由「下一圈的上段」代填；换成矩形即错（2×4 的底行被从左到右填）。而方阵里两道 guard 恒等价（guard 时刻必有 top=left+1、bottom=right+1），`<` 与 `<=`、合并与拆开在 59 上结果完全相同——**59 的用例对「guard 怎么写」没有区分度**，所以靠测试无法产生确信。

**Evidence:** 2026-11-23 用户汇报 + lc0059 第 20 行；脚本对比两种 guard 在 1..8 的全部 m×n 形状上的结果（合并严格 guard 错 24 种形状，均为长方形；两道独立 guard 全对）；n=4 追踪——合并版的 16 由第 3 圈上段写入，课上版由第 2 圈下段写入。

**Implications:** 自评信号连续多次被证实为准确（11-15 背诵痕迹、11-22 记忆偏多、本次碰运气），应按真信号处理：通过照常推进，但 gate 必须换成有区分度的任务。59 的 D+7（11-30）gate：两道独立 guard 版盲写 + 每道 guard 口述「替哪段挡哪种重复」；区分性练习用 54 的 2×4 用例（迁移失败可见）。验收通则：**当题目的定义域使两种机制等价时，通过不能作为区分证据，需换定义域**——54 之于 59（长方形）、81 之于 33（含重复元素）、152 之于 209（含负数）。参见 [[0011-form-deviation-blind-write]]（形态偏离是阳性证据）与 [[0009-framework-automated]]（越隔越会）。
