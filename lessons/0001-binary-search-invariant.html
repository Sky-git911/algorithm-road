二分查找：区间定义与循环不变量

约 25 分钟 · 前置：L0（见下方热身）· 实战：LeetCode 704 · 速查卡：binary-search.html

热身 30 秒（L0 折叠）

做任何题前先问：数据规模多大，目标复杂度是多少？记住这张表就够了： n ≤ 10³ → O(n²) 能过；n ≤ 10⁵ → 要 O(n log n) 或 O(n)；n 越大越接近 O(log n)、O(1)。 完整表在你的 00-算法基础.md。 今天这题：有序数组里找一个数——「有序」是信号弹，答案几乎总是二分，O(log n)。

为什么第一题就容易翻车

704 二分查找，思路 10 秒就能讲明白：看中间，砍一半。但自己写的时候， 「为什么死循环了？为什么漏了那个元素？」——坑从来不在思路，而在区间定义： 一会儿把 r 当「包含」，一会儿当「不包含」，循环条件、收缩语句就配套错了。

区间定义是一份合同：你先声明 a[l..r] 的 r 含不含，之后每一行代码—— 循环条件、l/r 怎么收缩——都必须履约。合同只签一种，签了就不改。

知识：前提、两种合同、一个不变量

二分的前提不只是「数组有序」，更一般的说法是判定单调： 每次看 mid，你能确定地排除一侧（target 不可能在那一侧）。有序数组里比大小是这样， 别的场景（比如后面会遇到的下界函数）也是这样——记住一般版。

两种合同，任选一种，坚持到底：

决策点合同 A：左闭右闭 [l, r]合同 B：左闭右开 [l, r)
r 初始值n - 1（最后一个元素）n（越界空端点）
循环条件l <= r（单元素也是合法区间）l < r（l == r 时区间已空）
a[mid] < tl = mid + 1l = mid + 1（相同）
a[mid] > tr = mid - 1（mid 必须排除）r = mid（r 本就不含）
区间为空l > rl ≥ r

为什么收缩不一样？看循环不变量：

不变量：每一轮循环开始时，若 target 存在，它必在当前区间内。 a[mid] ≠ t 说明 mid 已经比较过、被排除——闭区间的 r 是含端点的，所以必须 mid - 1 才能把 mid 排除掉； 开区间的 r 本来就不含自己，所以 r = mid 刚好。每一行收缩代码，都是在维护这条不变量。
mid 用 Math.floor((l + r) / 2)。JS 里别写 (l + r) >> 1： 位运算会把数字截断成 32 位有符号整数，下标一大就变负数。面试口述时可以补一句 「C++/Java 里我还会写 l + (r - l) / 2 防溢出」——JS 安全整数到 2⁵³ 不需要，但这句话值印象分。
