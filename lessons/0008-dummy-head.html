链表开场：虚拟头节点

约 25 分钟 · 前置：数组专题全部（不变量家族）· 实战：LeetCode 203（Easy）+ 707（Medium）· 本地基建 practice/_utils/list.js 已就位

链表和数组差在哪（30 秒）

数组：内存连续，下标即位置，找得快、插删慢（要挪后面所有元素）。 链表：每个节点 = 值 + 指向下一个的引用，内存散落，只能从头顺着走， 但插删只是「改两次指针」。JS 里没有内置链表——节点就是一个对象 { val, next }，对象引用就是指针（你天天写对象属性赋值，其实早就在操作指针）。

为什么需要虚拟头节点

链表删除/插入都需要操作目标的前驱（前驱.next 指向谁，谁就被接入或摘除）。 但真头节点没有前驱——于是「删头节点 / 在头部插入」处处要特判 if (head === …)。 解法：开头放一个不存数据的哨兵节点 dummy，让真头节点也有前驱—— 用一个哨兵，换掉一整类特判。

决策点规则（203 移除链表元素）
初始化dummy = new ListNode(0, head)，cur = dummy
审查对象永远是 cur.next（cur 自己已审查过）
cur.next.val === val摘链：cur.next = cur.next.next——cur 原地不动（新接上的 next 还没审）
不相等cur = cur.next 前进一格
终止cur.next === null；返回 dummy.next（新真头）
不变量（老朋友第五次登场）：cur 及其左侧的所有节点，值都不等于 val—— cur 就是「已清洁区」与「待审区」的分界刀痕。快慢指针的 [0..slow)、二分的 [l..r]、 滑窗的窗口、螺旋的剥圈边界，到链表上就是「cur 的位置」。模型换了衣裳，思想是同一件。
链表题是错题本②（有思路写不出）的高发区——你 README 第一周就预言过。三个高频坑： ① cur 与 cur.next 混用——删除永远操作 cur.next，因为你要的是前驱视角； ② 摘链后 cur 前进——[7,7,7] 全删场景立刻露馅（新 next 还没审就跳过了）； ③ 返回值——返回 dummy.next 而不是 dummy（dummy 是哨兵不是数据）。

亲手走一遍：哨兵审查

两个预设：标准场景（尾部的 6）和照妖镜场景（[7,7,7,7] 全删——专门检验「摘链后不前进」）。 每步先预测：这一步是摘链还是前进？cur 动不动？

    📋 完整题面 · 203 移除链表元素（Easy）

    给你一个链表的头节点 head 和一个整数 val，请你删除链表中所有满足 Node.val == val 的节点，并返回新的头节点。

    示例 1：head = [1,2,6,3,4,5,6], val = 6 → [1,2,3,4,5]
示例 2：head = [], val = 1              → []
示例 3：head = [7,7,7,7], val = 7       → []

    提示：列表中的节点数在 [0, 10⁴] 范围内；1 ≤ Node.val ≤ 50；0 ≤ val ≤ 50。

    📋 完整题面 · 707 设计链表（Medium）

    设计链表的实现。可以选择单链表或双链表。单链表中的节点应该具有两个属性：val 和 next。你的实现需要支持以下操作：

    • get(index)：获取链表中第 index 个节点的值（从 0 开始）。如果索引无效，返回 -1；
    • addAtHead(val)：在第一个元素之前添加；
    • addAtTail(val)：追加到最后一个元素之后；
    • addAtIndex(index, val)：在第 index 个元素之前添加（index 等于链表长度时追加；超过长度则不插入）；
    • deleteAtIndex(index)：删除第 index 个元素（无效则不删）。

    提示：所有操作中 index 均从 0 开始；1 ≤ val ≤ 1000；调用次数 ≤ 2000。
