二分·边界查找：从「找到它」到「找到分隔线」

约 25 分钟 · 前置：0001 · 实战：LeetCode 35（今天）/ 34（明天）· 速查卡：binary-search.html

为什么需要这一课

704 回答的是「在不在」（在 → 下标，不在 → -1）。面试官喜欢追问半步：「具体是哪一个？ 不在的话该插在哪？」——这就是 35 搜索插入位置和 34 查找元素的第一个和最后一个位置。 而且你要学的不只是两道题：「第一个 ≥ t 的位置」（lower_bound）是整个路线图里复用率最高的二分模型之一， 后面滑窗、DP 优化里它还会反复出现。

视角切换：不找元素，找分隔线

想象把数组一刀切成两段：左边全部 < t，右边全部 ≥ t。你要找的就是这条刀痕的位置—— 它天然就是「第一个 ≥ t 的下标」。所有的边界问题都变成这一刀：

问题怎么用这一刀
35 插入位置刀痕 = 第一个 ≥ t 的位置 = 插入点（没有 ≥ t 的元素时刀痕 = n，插末尾）
34 左边界刀痕处检查一下是不是真的等于 t
34 右边界对 t+1 再切一刀，退一格：lb(t+1) - 1
不变量升级——0001 是「若 t 存在必在区间内」；0002 变成 「分隔点左侧全部 < t，右侧全部 ≥ t，两段之外全部已确认，刀痕必在 [l, r) 之间」。 二分收缩的不再是「t 在哪」，而是「刀在哪」。

决策表：还是合同 B，只改一条

决策点0001 合同 B（找存在）0002 lower_bound（找刀痕）
初始化l = 0, r = nl = 0, r = n（相同）
循环条件l < rl < r（相同）
a[mid] < tl = mid + 1l = mid + 1（相同）
a[mid] > tr = mid等号并入 ≥：r = mid（mid 可能就是刀痕，不能 -1）
a[mid] === t命中，返回 mid
终止时区间空 → 返回 -1l === r 即刀痕，取值 [0, n]

和 0001 的唯一区别：命中「等于」时不再返回——等号并入 ≥ 分支，继续往左压 （左边可能还有等于 t 的，刀痕要的是最左边那个）。右端 r = mid 保持 0001 合同 B 原样， 因为 mid 本身可能是答案，减一就会漏。

最大坑：把 ≥ 分支写成 r = mid - 1。 0001 里「大于才减一」是因为 mid 已被排除；0002 里 mid 可能正是刀痕——减一等于把答案扔了。 判断标准只有一条：被移出区间的那一侧，必须已经被「确认」不可能是答案。

亲手走一遍：切一刀

9 个有序号（注意有重复的 3 和 7——重复正是边界问题的灵魂）。选一个 t，每步先口头预测 （这一步推进 l 还是回收 r？），再点「步进」。试试 4（不存在）：刀痕落在 3 和 5 之间，正是 35 的插入位。

    📋 完整题面 · 35 搜索插入位置（Easy）

    给定一个排序数组和一个目标值，在数组中找到目标值，并返回其索引。如果目标值不存在于数组中， 返回它将会被按顺序插入的位置。请必须使用时间复杂度为 O(log n) 的算法。

    示例 1：nums = [1,3,5,6], target = 5  → 2
示例 2：nums = [1,3,5,6], target = 2  → 1
示例 3：nums = [1,3,5,6], target = 7  → 4
示例 4：nums = [1,3,5,6], target = 0  → 0

    提示：1 ≤ nums.length ≤ 10⁴；-10⁴ ≤ nums[i] ≤ 10⁴；nums 为无重复元素的升序数组。

    📋 完整题面 · 34 在排序数组中查找元素的第一个和最后一个位置（Medium）

    给你一个按照非递减顺序排列的整数数组 nums 和一个目标值 target， 请你找出给定目标值在数组中的开始位置和结束位置。如果数组中不存在目标值，返回 [-1, -1]。 你必须设计并实现时间复杂度为 O(log n) 的算法解决此问题。

    示例 1：nums = [5,7,7,8,8,10], target = 8  → [3,4]
示例 2：nums = [5,7,7,8,8,10], target = 6  → [-1,-1]
示例 3：nums = [], target = 0               → [-1,-1]

    提示：0 ≤ nums.length ≤ 10⁵；-10⁹ ≤ nums[i] ≤ 10⁹；nums 是非递减排序的数组。
