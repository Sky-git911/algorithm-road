反转链表：改链三步的主场

约 25 分钟 · 前置：0008（虚拟头节点 + 改链三步）· 实战：LeetCode 206（Easy）· 开课仪式：默写改链三步

开课仪式：先默写改链三步

别往下滚。拿纸笔，把「改链三步」默写出来——昨天 quiz 的 Q3 你错的就是它。 写完再对照：

存 next → 改指向 → 移指针（先存后改）

昨天错这题不是坏事：错在哪，就说明半衰期在哪——今天整节课都在替你还这笔债。 206 的循环体就是这三步本身，一步不多，一步不少。

反转到底难在哪

逻辑上毫无难度：每个节点的 next 掉个头。难在你正踩着链走路， 脚下每一格的指针都在被你改——这是「边遍历边改链」的最纯样本（707 的 addAtTail 死循环就是这类操作的翻车现场）。对策不是小心翼翼，是把世界切成两半：

  • prev 身后：已反转世界——箭头全部朝左，由 prev 领衔；
  • cur 身前：未动世界——箭头仍朝右，由 cur 领衔；
  • next：动手前提前保住的桥——cur 掉头后唯一的退路。

两个世界以 cur 为界。每轮三步只干三件事：保桥、掉头、挪边界。

决策对照表

决策点规则（206 反转链表）
初始化prev = null，cur = head（prev 是已反转世界的头，开局为空）
循环条件cur !== null（未动世界还有货）
第一步 · 存next = cur.next —— 后继的唯一线索，掉头前先保命
第二步 · 改cur.next = prev —— 掉头，接上已反转世界
第三步 · 移prev = cur; cur = next —— 两个世界的边界各挪一格
终止cur 为 null 时 prev 恰是原尾 = 新头，返回 prev
不变量（老朋友第六次登场）：prev 领衔的链 = 原前缀 [0..i) 的逆序； cur = 原第 i 个节点。它是快慢指针「读写分工」的亲戚——slow=prev（写）、fast=cur（读）， 只是这次「写」的对象从数组值换成了指针本身。模型换了衣裳，思想还是同一件。
四个高频坑，三个你在 707 亲手踩过： ① 先改后存——next 取到的是改完的新值，后继失联（V1 自环同款）； ② 手痒加第四步——比如用 cur = cur.next 代替 cur = next， 掉头之后 cur.next 已经不是「下一个」了； ③ 返回 cur——循环结束时 cur 是 null，返回它等于返回空表； ④ 想给空表/单节点加特判——别。空表：cur=head=null，循环零次，返回 prev=null； 单节点：一轮即止。模板连续剧第三集：先问模板能不能吞，再考虑特判。

    给你单链表的头节点 head，请你反转链表，并返回反转后的链表。

    示例 1：head = [1,2,3,4,5] → [5,4,3,2,1]

示例 3：head = []          → []

    提示：链表中节点的数目范围是 [0, 5000]；-5000 ≤ Node.val ≤ 5000。
