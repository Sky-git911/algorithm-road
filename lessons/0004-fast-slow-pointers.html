快慢指针：原地造刀痕

约 25 分钟 · 前置：0001–0003（二分三部曲）· 实战：LeetCode 27（主线）+ 283（补充）· 速查卡：本课新增节

为什么数组「删」元素是个问题

数组在内存里是连续的，没有「真删」这回事——只能覆盖 + 约定「前 k 个有效」。 朴素做法每删一个就把后面整体前移，O(n²)；快慢指针一趟 O(n) 解决， 且只花 O(1) 空间。这也是你第一次写「原地算法」（in-place）：不新建数组，在原数组上手术。

模型：读指针探路，写指针站位

角色走法职责
fast（读）每轮必走探路、判定当前元素合不合格
slow（写）拿到合格元素才走标记「已保留前缀」的末端
判定动作
a[fast] 不合格fast++（slow 不动）
a[fast] 合格a[slow++] = a[fast++]（写入并双走）
fast 越界（到 n）终止，[0..slow) 即结果
不变量（第三次登场）：每一轮开始时，[0..slow) 全是合格元素（保持原相对顺序）， [slow..fast) 全是已判定的不合格元素。slow 就是保留区与弃区的刀痕—— 0001 找存在、0002 找刀痕、0004 原地造刀痕。判定条件一换，题目就换：27 判「≠val」，283 判「≠0」。
三个高频坑： ① 返回值——27 返回 slow（合格前缀的长度），不是 n 也不是 slow - 1； ② 尾部垃圾不用清——[slow..n) 里残留旧值是允许的，题目只看前缀； ③ 283 是「改原数组、无返回」——和 27 的「返回新长度」是两种不同的要求，读题先分辨。

283 两种写法（同一模型的两件外衣）： 覆写版——非零元素照 27 压到前缀，最后把 [slow..n) 填 0； 交换版——合格时 [a[slow], a[fast]] = [a[fast], a[slow]] 并 slow++，0 被自动换到后面。 两种都保持非零相对顺序，覆写版更贴本课模型，交换版少一趟填零。

亲手走一遍：去留流水线

两个预设：27 场景（val=3）和 283 场景。每步先预测：这个元素保还是弃？slow 动不动？ 注意观察「写入」发生的瞬间——数组内容在原地址上被改写。

    📋 完整题面 · 27 移除元素（Easy）

    给你一个数组 nums 和一个值 val，你需要原地移除所有数值等于 val 的元素，并返回移除后数组的新长度。不要使用额外的数组空间， 必须仅使用 O(1) 额外空间并原地修改输入数组。元素的顺序可以改变。你不需要考虑数组中超出新长度后面的元素。

    示例 1：输入 nums = [3,2,2,3], val = 3
      输出 2，nums 前 2 个元素为 [2,2]（之后的内容随意）
示例 2：输入 nums = [0,1,2,2,3,0,4,2], val = 2
      输出 5，nums 前 5 个元素为 0,1,4,0,3（任意顺序均可）

    提示：0 ≤ nums.length ≤ 100；0 ≤ nums[i] ≤ 50；0 ≤ val ≤ 100。

    📋 完整题面 · 283 移动零（Easy）

    给定一个数组 nums，编写一个函数将所有 0 移动到数组的末尾， 同时保持非零元素的相对顺序。请注意，必须在不复制数组的情况下原地对数组进行操作。

    示例 1：输入 nums = [0,1,0,3,12]  → 输出 [1,3,12,0,0]
示例 2：输入 nums = [0]            → 输出 [0]

    提示：1 ≤ nums.length ≤ 10⁴；-2³¹ ≤ nums[i] ≤ 2³¹ - 1。 进阶：能尽量减少操作的次数吗？
