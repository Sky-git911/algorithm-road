旋转数组二分：判定单调的第一次实战

约 25 分钟 · 前置：0001 / 0002 · 实战：LeetCode 153 + 33（脚手架已备）· 速查卡：binary-search.html

这课为什么值一节

0001 埋了一句话：二分的前提是「判定单调」，不是「数组有序」。旋转数组就是这句话的试金石—— 整体看是无序的（[40,50,60,10,20,25,30,33]），但 mid 一刀切下去，至少有一半是完全有序的。 只要每轮能「确定地排除」一半，二分就成立。学完这课，「什么时候能用二分」这个判断力才算真正建立。

153 找最小值：断层在哪里

旋转一次的数组 = 两段有序的拼接，最小值就是断层点。判据只有一个： 拿 a[mid] 和 a[r] 比（注意是右端）。

比较结论收缩
a[mid] > a[r]断层在 mid 右侧——mid 及其左侧全部比 a[r] 大，都不可能是最小l = mid + 1
a[mid] < a[r]mid 到 r 连续上升，最小值在 [l, mid]（mid 本身可能是）r = mid（不能 −1）
不变量：最小值的下标始终在 [l, r] 内。循环条件 l < r （收敛到单点即答案，l === r 时停）——这是 0002 的「分界型」收缩，只是端点语义用闭区间更顺手。 两个收缩都是安全的：被排除的一侧已经「确认」不含最小值。
为什么比 a[r] 不比 a[l]？数组未旋转时 a[l] 本身就是最小值， 比 a[l] 会把 l 错误右推。a[r] 永远在「断层之后的那一段」里，是可靠的路标。 （153 保证元素互异所以没有等号分支；有重复的版本是 154，进阶，现在不碰。）

33 搜索：先判哪半有序，再砍

每轮两步走，写之前在草稿上画出四行决策：

第 1 步：哪半有序？第 2 步：target 在有序半边里吗（端点一夹）收缩
若 a[l] <= a[mid] → 左半 [l, mid] 有序在（a[l] <= t <= a[mid]）砍右：r = mid - 1
不在砍左：l = mid + 1
否则 → 右半 [mid, r] 有序在（a[mid] <= t <= a[r]）砍左：l = mid + 1
不在砍右：r = mid - 1

命中 a[mid] === t 随时返回；区间空了返回 -1。合同 A（左闭右闭、l <= r）—— 因为这题是 0001 的「存在型」而非「分界型」。动笔前先写合同声明。

亲手走一遍：找断层（153）

三种形态各试一遍（未旋转那个最值得看：体会 a[r] 路标怎么避开 a[l] 的陷阱）。 每步先预测：断层判定走哪个分支？l 还是 r 动？
